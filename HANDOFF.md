## 1. Що це за продукт (суть за 30 секунд)

**VideoCombine** — десктопна (.NET 8 / WPF) програма-комбайн для **автоматизованого створення завершених відео**. Дві гілки:
- **Переробка:** завантажити чужі/свої відео (YouTube тощо) → нарізати → унікалізувати → зібрати нове відео.
- **Створення з нуля:** ідея/текст → AI-сценарій → сцени → генерація картинок/відео + озвучка → зібрати.

Гілки **схрещуються**: озвучка зі сценарію + відеоряд із нарізок («голос + b-roll»).

**Мета — на виході готове відео, яке не треба доробляти в монтажці.** Не напівфабрикат. Це впливає на пріоритети (завершеність важливіша за голий обсяг).

Уся важка робота з відео — через **FFmpeg** (зовнішній .exe). Завантаження — через **yt-dlp** (.exe). Програма — зручна оболонка, що складає команди й керує пайплайном.

## 2. Архітектурний фундамент — «усе є крок» (НЕ ПОРУШУВАТИ)

Кожна дія = **крок** зі спільним інтерфейсом `IStep` (вже в скелеті: `VideoCombine.Core/Pipeline/IStep.cs`). Завантаження, нарізка, ефект, апскейл, озвучка, склейка — усі реалізують `IStep`.

- **Додати функцію = додати клас, що реалізує `IStep`.** Решта не змінюється.
- Кроки не знають один про одного — спілкуються лише через `PipelineContext` (спільна «коробка»).
- **Пайплайн = список кроків.** Виконуються ПО ЧЕРЗІ (конвеєр). Порядок поки фіксований і розумний; галочки лише вмикають/вимикають кроки (драг-н-дроп — на потім, але позиція кроку вже зберігається в рецепті, тож додати легко).
- **Паралельність — УСЕРЕДИНІ кроку** (багато незалежних сегментів), не між кроками. Ліміт залежить від типу: FFmpeg/CPU ~8, AI-апскейл/GPU 1-2, завантаження 2-4, хмарні API — за лімітом провайдера.
- **Кожен крок ЗОБОВ'ЯЗАНИЙ звітувати прогрес** (`IProgressReporter`) — це частина контракту. GUI це показує (лоад-бари, лог).
- **Патерн провайдера:** апскейл, TTS, LLM, генерація медіа — кожен має спільний інтерфейс і взаємозамінні бекенди (локальні + хмарні), один дефолтний. Хмарні часто **асинхронні** (відправ → poll job-id) — інтерфейс має це підтримувати.

## 3. Структура рішення (вже створена в скелеті)

```
VideoCombine.sln
└── src/
    ├── VideoCombine.Core/        ← МОЗОК, НЕ знає про WPF (щоб ядро жило в консолі/тестах/майбутній веб-морді)
    │   ├── Pipeline/  IStep, PipelineContext, PipelineExecutor, IProgressReporter, IPipelineProgress
    │   ├── Steps/     CutStep.cs (готовий приклад повноцінного кроку — зразок для решти)
    │   ├── Providers/ IUpscaleProvider.cs (зразок патерну провайдера)
    │   ├── External/  ProcessRunner.cs (запуск ffmpeg/yt-dlp)
    │   ├── Recipes/   Recipe.cs, RecipeStore.cs (JSON-рецепти)
    │   └── Models/    Models.cs (SourceVideo, Segment, Scene...), AppSettings.cs
    ├── VideoCombine.App/          ← WPF (MVVM), лише GUI. Залежить від Core. Core від App — НІКОЛИ.
    └── VideoCombine.Tests/        ← тести Core без GUI (є RecipeStoreTests)
```

**Залізне правило:** App → залежить від Core; Core → НІКОЛИ не знає про App. (Це робить дешевою майбутню веб-морду після MVP.)
**Наслідок:** жодної відео-логіки в коді вікон WPF.

## 4. Ухвалені рішення (не переглядати без причини)

**Таби GUI:** Джерела · Конструктор · Виконання · Налаштування.

**Джерела:** перемикач гілки (з відео / з ідеї); ЄДИНЕ поле вставки (приймає й одне посилання, й пачку по рядках); drag-and-drop файлів; мініатюри в рядках; дедуплікація+валідація з підсвіткою; вибір якості; кнопка «Проаналізувати все». **Аналіз лінивий:** FFprobe одразу (дешево), Whisper — лише коли крок цього потребує або вручну.

**Конструктор:** дві колонки (зліва кроки з галочками, згруповані за категоріями + короткий підсумок налаштувань праворуч від кроку + стан «треба увага»; справа — панель налаштувань вибраного кроку). БЕЗ акордеону. Зверху рядок рецепта (вибір/зберегти/дублювати). Залежності кроків підсвічуються (напр. b-roll «за змістом» потребує Whisper).

**Унікалізатор:** список вмикабельних ефектів, 4 групи — геометрія (кроп/формат, дзеркало, зум, поворот, паддінг, blur-поля), колір/текстура (яскравість/контраст, насиченість/відтінок, шум, різкість, віньєтка), час (швидкість, обрізка країв), накладання (водяний знак, текст). **Превʼю кадру «до/після»** через той самий движок ефектів на одному кадрі. **Рандомайзер:** тільки косметичні ефекти (НЕ структурні — інакше відео стрибає), 3 режими на ефект: вимк/фікс/рандом-з-діапазоном, кожен сегмент отримує своє значення.

**Апскейл:** FFmpeg-scale (лок.), Real-ESRGAN (лок., GPU), Зовнішній API (Topaz/WaveSpeedAI/SeedVR2/Google AI + «свій endpoint»). Хмарні — асинхронні.

**Озвучка/TTS:** ElevenLabs / OpenAI / локальний Piper. Деталі для ElevenLabs: Stability/Similarity/Style/Speed/Speaker Boost (у блоці провайдера).

**LLM:** будь-який бекенд (OpenAI/Anthropic/Google/Ollama) + дефолтний. Використовують: сценарій, рерайт, розбивка на сцени, розумний b-roll.

**Генеративна гілка:** редактор сцен (storyboard) — кожна сцена має 3 поля (озвучка / промпт картинки / промпт руху) + мініатюру. Промпти: авто (LLM) → ручна правка. Генерація: посценно (доводити) АБО все одразу. Медіа-генерація — хмарні API. Референси (до 4 картинок) для консистентності. **Кеш згенерованих медіа** (дорого відтворювати — виняток із «стан не зберігаємо»). Клік на мініатюру → лайтбокс у повній роздільності.

**B-roll зшивач (схрещення гілок):** НЕ окрема гілка, а крок у спільному хвості. Вибір «чим заповнити кадр» (AI/нарізки/змішано) + рівень підбору (хронометраж / зміст через Whisper / розумний через LLM).

**Склейка/монтаж:** порядок сегментів (послідовно/випадково/список); переходи (Cut дефолт/Fade/Crossfade/Зсув) + тривалість; ручні написи (заголовки, нижня третина, заклики) — окремо від субтитрів-з-мовлення (ті — окремий Whisper-крок). Cut безкоштовний, Crossfade сповільнює — дефолт Cut для багатьох сегментів.

**Вивід:** loop (повтор/seamless/boomerang/до тривалості); метадані (лишити/прибрати/замінити); профілі платформ (YouTube/Shorts/TikTok/Reels, дефолт mp4/H.264 1080p); експорт відео (наш FFmpeg-рендер).

**Виконання:** загальний прогрес (крок N з M) + поточний крок (дія, деталь, %, час «~», к-сть процесів) + лог (3 рівні: успіх/попередження/помилка) + Пауза/Скасувати. **Політика помилок:** дрібний збій (битий сегмент) — пропустити+лог, не валити; критичний (нема exe/місця/ключа) — зупинити.

**Налаштування:** шляхи до exe (зі станами), API-ключі (захищено, ОКРЕМО від JSON-рецептів), ліміти одночасності, папки.

**GEO/профіль ніші:** окремий від рецепта профіль КОНТЕНТУ (мова, регіон, тон, аудиторія, стиль) — впливає на текстові кроки. Дефолтний є; можна додавати/зберігати свої. Окремий JSON.

**Генерація обкладинки (thumbnail):** окремий генеративний крок, дефолтний пресет стилю + свої.

## 5. Свідомо ВІДКЛАДЕНІ / відкриті розвилки

- **Складна моушн-графіка / Remotion:** ПОКИ без нього — починаємо на FFmpeg + WPF (малювати кадри-вставки через WPF RenderTargetBitmap → FFmpeg, місток NReco.VideoConverter). Це рішення «спершу простіше», НЕ «графіка не треба». Якщо WPF-вставок забракне для відчуття завершеності — повернути Remotion (ліцензія: безкошт. для соло/≤3 осіб; React/Node.js) або Twick (MIT, безкошт.) як начинку кроку «рендерер вставок». Двері відчинені через патерн кроку.
- **Експорт проекту CapCut/XML:** замість власного рендеру — згенерувати проектний файл для ручного доведення. Як отримати схему: еталонний проект у CapCut → експорт XML → за зразком написати генератор. Ще один крок виводу. Пріоритет — після MVP.
- **Мульти-акаунти + черга публікації:** напрям дистрибуції, не виробництва. Поза MVP, занотовано.
- **Стрім/RTMP:** відхилено — інша програма.
- **Веб-морда:** колись після MVP, нова оболонка над тим самим Core.
- **Стан прогону не зберігаємо** (технічні файли), АЛЕ згенеровані медіа кешуються.

## 6. План реалізації (фази — почати звідси)

**Фаза A (фундамент)** — здебільшого вже в скелеті: `IStep`, `PipelineContext`, `PipelineExecutor`, звітування. Перевірити збірку, прогнати тест.

**Фаза B (перший робочий ланцюг — НАЙВАЖЛИВІШЕ для MVP):**
- `DownloadStep` (yt-dlp) + `AnalyzeStep` (ffprobe, ліниво).
- `CutStep` — вже готовий зразок.
- `AssembleStep` (склейка).
- WPF: таб «Виконання» з реалізацією `IPipelineProgress` (лоад-бари+лог).
- **Ціль фази:** «вставив посилання → отримав нове зібране відео». Перший відчутний результат.

**Фаза C:** таб «Конструктор» (список кроків + панель налаштувань), JSON-рецепти через `RecipeStore`, профілі платформ.

**Фаза D:** провайдери (апскейл: спершу FFmpeg-scale → потім AI; TTS: один → решта), Whisper, loop, паралельність усередині кроків.

**Фаза E:** генеративна гілка (сценарій → сцени → медіа → хвіст), LLM-провайдер, редактор сцен, b-roll зшивач.

**Фаза F:** поліш — переходи, музика, превʼю, обробка помилок, унікалізатор-рандомайзер, GEO-профілі, обкладинки.

> Логіка порядку: спершу довести, що каркас і переробка працюють (A-C), потім провайдери (D), і лише тоді дорога генеративна гілка (E) — вона найдорожча (платні API) і спирається на готовий спільний хвіст.

## 7. Технічні нагадування

- .NET 8, C# latest, nullable enable. WPF-проект — `net8.0-windows`, Core — чистий `net8.0`.
- MVVM: рекомендовано CommunityToolkit.Mvvm.
- yt-dlp і ffmpeg — зовнішні .exe, запускати через `ProcessRunner`, не шукати .NET-біндинги. (Обгортка FFMpegCore — опційно для зручності складання команд.)
- Усе важке — у фоновому потоці, GUI не блокувати.
- Перевірка наявності exe при старті + зрозуміла підказка, якщо немає.
- API-ключі — у захищеному сховищі ОС, не в рецептах.
- **Кожна зміна → запис у `docs/CHANGELOG.md`** (шаблон і правила — на початку того файлу), у тому ж коміті. Якщо зміна зачіпає ухвалене рішення — оновити й `VideoCombine_Architecture.md`.
- Зовнішні .exe запускати **лише** через `ProcessRunner` (вбиває процес із дочірніми при скасуванні/виході — журнал, запис 001).
- Дробові числа в аргументи ffmpeg/ffprobe/yt-dlp — **лише** через `FfmpegFormat` (крапка незалежно від локалі Windows — журнал, запис 003).
- У сегмента є ознака `HasAudio`; крок, що створює сегменти сам, має виставити її чесно (журнал, запис 002).
- Авторське право: користувач працює в межах fair use, програма технічно нейтральна — не вбудовувати ні обмежень, ні «обхідних» механік.
